# HSC 门户轻量备份与运维方案

版本：0.2　核查／更新日期：2026年11月19日

用户已同意简化备份与运维方向，按低流量、低变更频率、由志愿 Board 运营的非营利俱乐部定位。沿用 Sites／Cloudflare，优先利用平台现有恢复能力，只增加必要的独立副本和故障提醒。

**每周一份、保留最近 4 份是根据用户简化要求采用的 v1 默认，不是用户逐条确认的周期。** 本文描述方案及上线前条件，不表示备份、平台恢复或提醒已经启用。

## 1. v1 默认做法

| 项目 | 默认做法 |
| --- | --- |
| 数据库快速恢复 | 优先使用平台现有 D1 Time Travel；先确认实际恢复窗口、支持入口及负责人可执行的路径 |
| 独立备份 | 每周生成一份完整备份并加密保存到俱乐部控制、独立于生产账户的存储，保留最近 4 份；包含数据库快照、附件文件清单及对应文件 |
| 重大更新 | 数据结构、会员／财务迁移或关键业务改动前额外备份；变更验收通过、确认无需回退后清理这份临时副本，不影响最近 4 份周备份 |
| 文件保护 | 图片与 PDF 使用不可变对象键，更新生成新文件，D1 保存引用；清理文件前核对保留的备份仍能恢复其引用 |
| 故障提醒 | 只接网站不可用和备份失败／逾期两类提醒，发送给约定的维护联系人；恢复时结束提醒，避免重复轰炸 |
| 恢复验证 | 上线前在隔离环境完成一次完整恢复；以后在重大变更或负责人交接时再验证 |
| 交接材料 | 保留一页操作指引：站点与账户入口、备份位置、解密方式、恢复步骤和维护联系人；密码及密钥通过安全渠道管理 |

周期任务一旦接通，应记录最近成功时间、文件大小及校验值。平台接口或独立存储未接通时，状态明确显示“未启用”；执行失败时显示失败，不把导出按钮存在视为已有备份。

本版本不设固定季度演练、轮班值守或额外 Sentry／Datadog。运维提醒只限上表两项，原有业务邮件与通知不因此改变。

## 2. 平台能力与尚未落实的部分

继续复用既有 Sites 项目、Worker 和 D1。R2 是已选定的文件存储方案，实际绑定及运营配置以验收记录为准；不为备份另建替代站点或迁往个人 Cloudflare 账户。

当前 Sites 技能支持 D1／R2 逻辑绑定和发布时数据库迁移；工具支持数据库概览、有限分页只读数据及近期 Worker 日志。**未发现完整 D1 导出、Time Travel 恢复、R2 桶规则或原生告警的 Sites 配置接口。** 因此，完整备份和恢复的执行路径仍需平台能力或授权账户支持，不能写成今天已自动运行。

D1 官方 Time Travel 在生产存储后端默认提供，Free 的恢复窗口为 7 天、Paid 为 30 天，数据库历史及恢复不额外收费；这不是对 HSC 实际套餐和可用恢复权限的确认。恢复会覆盖原数据库，必须先保存当前状态并确定目标时间点。[Time Travel 官方说明](https://developers.cloudflare.com/d1/reference/time-travel/)

完整 SQL 导出需要 Wrangler 或 REST API 权限，导出期间会阻塞其他数据库请求，应安排低峰并先验证耗时。官方 Workflows＋R2 示例可作为实现参考，但所需账户、数据库及导出令牌不等于当前 Sites 已提供。[D1 导出与限制](https://developers.cloudflare.com/d1/best-practices/import-export-data/)、[官方备份工作流示例](https://developers.cloudflare.com/workflows/examples/backup-d1/)

R2 未实现 S3 GetBucketVersioning／PutBucketVersioning；v1 以不可变文件键和应用引用记录保留所需文件，不声称已启用原生对象版本管理。[R2 S3 兼容表](https://developers.cloudflare.com/r2/api/s3/api/)

应用分页导出不能保证跨表一致性，也不覆盖全部账号、权限、订单和附件恢复需求。源码版本回退不能代替数据库恢复；失败部署可能已经应用迁移，恢复时必须匹配代码、schema 和数据版本。

## 3. 简化运维仍保留的保护

- 备份与恢复仅限授权维护人员；备份加密，解密材料与副本分开保管，不进入公开 Git 仓库、网页或聊天。
- 独立副本不能只存在于同一生产账户，负责人交接时须验证新负责人能找到副本、取得解密方式并执行恢复。
- 周备份清理只针对备份副本，不据此删除生产会员历史、财务资料或政策同意记录；文件清理须覆盖保留快照的引用需求。
- 监控探测只返回最低限度的可用性信息，不公开会员资料、依赖细节或密钥。备份逾期提醒需能发现任务根本未运行的情况。
- 恢复先在隔离环境验证账号与权限、必要业务记录及附件；不直接覆盖生产来试验。未经演练不承诺 RTO（恢复耗时）或 RPO（数据损失窗口）；每周独立备份也不等于分钟级灾难恢复。
- 涉及收款时必须保留支付事件去重、防重复扣款及恢复后对账：按支付服务商实际交易核对备份之后的支付、退款和分期，不能因回滚或重试再次扣款。

## 4. 上线前需要满足

1. 确认平台实际可用的恢复窗口、完整导出与恢复执行方式，以及对应权限。
2. 落实俱乐部控制的独立存储、加密方式和维护联系人，完成一份真实完整备份并验证校验值。
3. 完成一次隔离恢复，验证数据、文件与权限能够配套恢复，留下简短操作记录。
4. 接通网站不可用、备份失败／逾期两类提醒，验证接收与恢复通知；实际发送测试另按授权执行。

现有赛事官网同步任务继续保留，不重复创建，不恢复已删除的会话 heartbeat。本方案本身不新建调度、购买服务、发送通知或修改生产配置。

## 5. 今天 v1 与费用

今天 v1 可交付应用级内容导出、最小健康检查及操作指引；实际完成情况以实现和验收记录为准。这些不等同于完整数据库备份、独立副本、平台恢复或自动提醒已接通。缺失部分如实列为上线前待办。

费用优先控制在既有托管和必要存储内，暂不引入额外运维平台。R2 Standard 官方公开价为 US$0.015／GB-month，另有操作请求计费及免费额度；是否增加实际费用取决于 Sites 条款、已有用量、备份体积及独立副本位置，**不承诺免费或固定月费**。[R2 价格](https://developers.cloudflare.com/r2/pricing/)

平台能力依据为当前安装的 Sites 技能 `references/storage.md` 及数据库只读、Worker 日志工具元数据。官方资料核查日期为 2026年11月19日；本方案未查询私人会员行数据，未改动生产配置。
