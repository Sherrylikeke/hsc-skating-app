# HSC 俱乐部门户 PRD

版本 1.0 · 2026年11月19日 · 当前需求基线

本项目在现有 HSC 应用上扩展俱乐部官网、报名和收费能力，最终将 HSC 自有业务迁出 Uplifter。保留原网站栏目、功能和主要操作习惯，重点更新外观。官网作为默认首页，现有比赛赛程保留会员入口；官网 Schedule 始终表示课程课表。

用户要求今天交付 PRD 和 v1。本文据已确认决定成文，将尚未决定或缺乏资料的内容单独列出。**今天的 v1 是本地可运行的审阅与功能验证版本；生产切换必须等待完整官网、报名和付款验收。** 现有线上站点与会员赛程继续运行。

依据：[现状发现](portal-findings.zh-CN.md)、[决策记录](portal-decisions.zh-CN.md)、[轻运维方案](portal-operations.zh-CN.md)。原 v0.9 PRD 保留为历史草稿，不再作为当前技术选择依据。

## 1. 产品边界与成功标准

面向访客、家长／选手、教练、获准内容编辑和俱乐部管理员。家长仍可按熟悉栏目找课、查看详情、登录、选择选手、确认政策、报名和付款；Board 能自行维护内容，并按授权处理会员、报名及财务业务。

- 31 个已核查入口保留对应页面或明确映射，原栏目顺序和归属不变。
- 旧系统实际在用的规则与业务结果保持等价；会员后台尚未看过的步骤不能宣称已经复刻。
- 保留既有 HSC 赛程、历史数据、私人关系和账号权限；不以门户报名或姓名匹配扩大私人授权。
- 保留现有 Logo，探索新配色。v1 使用深青绿、浅冰绿与白底，红色 Logo 保持原样；这是一份可评审设计，不锁定最终色板。
- 适合低维护非营利组织：复用现有基础设施和账号，不增加重型 CMS、运维平台、值班制度或无关功能。
- 最终统一切换，避免在正式运营中长期将官网与报名付款分散到两个系统。

不增加营销 CRM、捐款平台、在线投票、新原生手机功能或外部协会系统替代。Skate Ontario／Skate Canada 等独立服务按原职责保留链接。

## 5. 内容后台与权限

管理员通过服务端给活跃会员单独授予内容编辑权限。编辑可直接发布，不设双人审批；编辑权不带来私人会员资料、家庭关系管理、收件箱或财务操作权限。停用账号与撤销编辑权均即时生效。

- 草稿与已发布内容分开；访客接口只返回已发布内容及公开原始快照。
- 保存、发布产生递增版本，并记录操作人和时间。使用预期版本号防止多人编辑相互覆盖。
- 恢复历史内容先加载进编辑器，经编辑确认发布为新版本；不删除后续历史。
- v1 编辑纯文本标题与正文，避免直接执行任意 HTML；目录价格和业务规则不通过文字编辑器偷偷改变。
- 文件访问由服务端控制，私有文件不得通过公开 URL 绕过。公开文件只存批准公开的俱乐部素材。
- 内容导出包含门户正文、历史版本和文件元数据，不包含完整数据库或文件字节。不得将导出按钮当成已完成备份。

数据库新增表：`hsc_portal_pages`、`hsc_portal_versions`、`hsc_portal_editors`、`hsc_portal_media`、`hsc_portal_contacts`、`hsc_portal_cart`。保留现有会员和赛程表。新增迁移为 `0008_sweet_blur.sql`，上线时按 Sites 支持流程应用，不在请求处理中建表。

## 6. 报名、支付与迁移的最终要求

报名流程以原站实际字段与顺序为准：栏目 → 查课 → 详情 → 登录／创建账号 → 返回报名上下文，之后按后台核验补齐选手、政策、购物车与付款步骤。

1. 资格、金额、折扣、定金抵扣、会员费、税费和取整由服务端计算，不能信任浏览器提交金额。
2. 课程名额与订单／支付状态一致，最后名额竞争、失败、取消、超时与延迟回调不得超卖或重复入班。
3. Stripe 支付事件验签、去重并持久记录；重试和恢复不能重复扣款，前端返回成功不能单独认定已付款。
4. 有限分期保留总额、期次、原扣款日期与明确终止，不将学期费用改为无限续订。
5. 原订单、已付、欠款、信用余额、剩余分期、政策同意及旧 ID 可追踪；逐户样本与财务总额均需对齐。
6. 旧会员激活不自动合并同名档案、认可家庭关系或提高权限。现有 HSC 密码和账号不被导入覆盖。
7. 旧卡资料由支付商按其安全流程迁移或重新绑定；普通会员 CSV 不能承诺无感迁卡。
8. 旧退款、争议、未到期扣款和退出合同应有处置记录；切换时同一笔未来款项只有一个系统负责收取。

上列是正式上线必须具备的能力，尚未在本次未启用的收款模块中实现或验收。采用 Stripe Payments 不代表已开商户、接通扣款或选择 Billing。

## 8. 轻量运维与费用原则

适配志愿者运营和低变更频率。v1 默认优先平台现有 D1 恢复，每周一份独立加密备份保留最近 4 份；重大更新前增加临时副本，确认无需回退后清理。首次正式上线前做一次隔离恢复，以后在重大变更或负责人交接时验证。

只设置网站不可用和备份失败／逾期提醒，发送给明确的维护联系人；无轮班值守、固定季度演练或新 Sentry／Datadog 账户。每周备份周期不用于删除生产财务、会员历史或同意记录。

D1 官方提供短期恢复，但 HSC 在 Sites 下实际窗口、权限和执行入口尚未确认。现有 Sites 工具可读数据库概览、有限行和日志，没有本轮可用的完整备份／恢复配置接口。R2 用不可变对象路径保存版本，不宣称开启其不支持的 S3 BucketVersioning。

`/api/health` 只返回最低限度可用性，不泄露私人记录或配置；内容导出仅为编辑运营工具。完整备份、独立副本、自动提醒均必须接通并验证后才能标为运行中。费用按实际托管和存储用量核实，不承诺免费或固定账单。详细来源及操作要求见 [运维方案](portal-operations.zh-CN.md)。

## 9. 验收与统一切换

本次本地验收应覆盖：31 个页面返回、代表页面桌面／手机渲染、搜索和详情、登录返回、购物车账号隔离、草稿不公开、直接发布、冲突保护、撤权、上传与私有文件保护、联系收件箱隔离、健康检查，以及既有会员／语言相关回归。

生产切换前另须完成：真实新旧任务对照、所有费用规则样本、并发名额／支付异常测试、迁移总额与逐户对账、旧分期停扣／新分期接续、邮件送达、完整备份恢复、Board 实际任务验收、域名与旧链接兼容。公开内容验收不能替代财务与登录后验收。

发布失败或回退前先确认已应用数据库迁移和已发生付款；代码版本回退不自动恢复数据库，不能重新开启旧扣款造成重复收费。
