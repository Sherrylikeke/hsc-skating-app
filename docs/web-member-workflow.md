# 网页会员入口完善 · 2026-10-23

本轮以 `main` 的 V12 网页为基线，手机分支 `mobile/capacitor` 保持不动。只完善已有网页流程，不开放注册、不配置邮件、不改变站点访问范围或数据库结构。

## 第一步：基线与问题定位

确认工作树干净、原私人网站为 V12、原小时同步任务及 Worker/D1 保留。检查发现：管理员主页默认展开登录设置；主页没有添加选手时误提示没有已批准关系；108 位候选缺少搜索；入口初始化将各种资料读取失败混同为会话失效，部分分支会吞掉错误。

## 第二步：主页与选择流程

- 管理员凭据设置仍可展开，但默认收起；不会删除恢复入口或修改凭据。
- 空主页提示明确引导在“我的选手”添加，不把主页偏好与批准关系混为一谈。
- `homeSkaterChoices` 使用 NFKC、大小写归一化和分词，按姓名/编号过滤；排除已经加入的 ID，不修改原名单，不合并同名选手。
- 搜索改变时清除未提交选择；无结果、名单尚未读取和全部已添加分别提示。没有有效选择时不能提交，最终候选和账号归属仍由服务器验证。

## 第三步：错误与会话边界

- `readMemberResponse` 保留 JSON API 的真实 HTTP 状态和错误；HTML 网关、损坏 JSON、无效响应形状归为资料读取失败，不冒充登录过期。
- `recoverMemberSession` 只在真实 JSON 401、当前身份允许恢复时尝试一次；403、503、网关或网络错误直接交给页面显示。恢复失败或第二次 401 都不循环重试。
- 当前允许恢复的身份仍是已验证的密码身份或既有所有者恢复路径；服务端身份、签名会话、禁用状态及角色检查不变。这个前端判断不授予权限。
- 每次重新读取会员资料清除旧管理/通知/赛程状态；认证或准入失败、退出、接受邀请后重新登录、撤销自身会话时清除相关客户端视图与敏感编辑状态。
- 管理员/教练界面同时检查当前角色与 active 状态；失去管理员角色后返回主页，不留在已移除的管理标签页。界面判断只是显示防护，实际权限仍由服务器执行。

## 第四步：验证与发布

新增 `node scripts/check-member-client.mjs`，以纯模拟检查 API 状态、HTML/JSON 异常、恢复次数和权限、服务故障、搜索结果、同名独立、无结果及原名单不变。

同时执行 Web 类型、语言、原账号权限/邮件/提醒隔离回归、官方同步客户端、赛程/出场顺序、粘贴和选手历史检查；使用原 Sites 官方构建/归档流程，确认来源提交一致后私人部署。生产浏览器只检查已有所有者会话、搜索/清空和页面提示，不为验收新增账号、关系、发送邮件或修改选手偏好。

最终提交、版本、测试结果和截图记录在用户交付文档中。没有执行的设备、邮件送达或普通外部会员访问不能写作通过。

## 后续边界

原官网同步未识别格式仍保留旧值并标待核对；本轮不把所有格式识别算作完成。已记录的 9 项依赖安全发现仍须兼容整改；真实邮件服务、发件域名、注册激活和外部访问许可仍待后续明确配置。保留站点所有者访问范围，不通过公开站点绕过这些问题。
