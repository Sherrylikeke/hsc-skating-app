# HSC Phase 2 管理员说明

## 登录与访问边界

原站点及原 D1 保持不变。首页为会员入口，`/workspace` 保留赛程、历史图表和筛选，`/coaches` 为管理员维护旧教练文本的页面。

Sites 托管 ChatGPT 登录、回调与身份 cookie。应用不收集密码。服务端以 Sites 验证的站点用户 ID 作为账号主键；角色选择、姓名、URL 和客户端传入的身份字段均不能授予权限。

应用另有8小时服务端会员会话，cookie 为 `__Host-hsc_session`，设置 Secure、HttpOnly、SameSite=Lax。数据库仅存随机会话令牌的 SHA-256；每次请求重新检查账号状态、会话版本、会员准入和有效关系。退出、撤销会话、停用账号和解除关系分别立即生效。写操作必须来自同源 JSON 请求，并执行服务端限速。

首次设置必须在现有仅所有者可访问的边界内完成。已核实的站点所有者邮箱 `sherrylikeke@gmail.com` 首次进入会员入口时成为管理员，站点用户 ID 写入 `hsc-admin-bootstrap`，以后不会自动重新授予被撤销的管理员角色。其他账号先进入 pending 状态，不能读取私人赛程。最后一个管理员不能被停用、降级，或通过接受普通邀请意外降级。

## 会员准入和邀请

1. 用自己的账号打开首页，选 Admin，再点“进入会员入口”。
2. 在“会员管理”逐位核对候选选手。108位历史名单不是会员白名单，初始没有自动批准任何一位。确认训练关系、代表俱乐部与全名状态后勾选准入。
3. 核实家长、选手或教练本人的 ChatGPT 登录邮箱。系统没有家长邮箱数据，不会从比赛名单推断监护人。未成年人的账号和家长关系必须由管理员明确确认。
4. 创建对应角色的邀请，明确选择允许绑定的选手。家长可多孩子，选手账号只能绑定一个本人资料，教练允许多人关联同一选手。教练文字候选名单不等于已验证账号。
5. 将一次性代码通过已确认的联系方式人工交给本人。代码只显示一次，数据库保存哈希，默认48小时到期。没有邮件自动发送；丢失时撤销旧邀请再生成。邀请只能由指定邮箱的已验证账号接受一次。
6. 受邀人在首页输入代码，接受后重新进入会员入口。没有邀请者可提交姓名匹配和身份核对申请，管理员核验后批准；姓名匹配本身没有访问权。同名选手用独立编号区分。
7. 名单外的人可以提交申请；管理员新增资料、确认准入，再邀请或明确绑定。家长可在账号已批准后逐个添加自己的孩子。

教练可通过工作区申请关联已有选手或提交新选手信息。所有新增/争议关联由管理员确认。批准后增加关系，不覆盖另一位教练。教练可主动解除自己的关系。账号换角色会撤销旧角色关系；停用、取消准入、解绑后每次 API 立即重新计算访问权。

保留 Breken 的 Hamilton 训练关系和比赛代表俱乐部差异。Nathaniel 全名未知时保持“全名 / 身份待确认”，不会按名字自动匹配官网记录。旧教练文本仍按用户保存的拼写显示；认证账号关系独立维护，不自动改写31条原始教练资料。

## 赛程与教练要求

管理员可查看所有候选、赛程与日志；Parent/Skater 仅获得已批准关系内的私人安排；Coach 获得自己关联选手的安排与汇总。赛事名称、官方文件、参赛公开名单、冰场、成绩来源属于公开赛事资料；会员身份、账号邮箱、私人备注、要求、回执和通知属于按关系隔离的资料。其他选手的历史档案 API 也会拒绝越权请求。

教练在“教练要求”选择一个或多个关联选手，填写准备、集合、装备或训练要求，可关联一场赛事及其官方分项、设置有时区的截止时间。发送者由服务端决定。家长/选手分别为每个孩子记录已读与确认；编辑产生新版本，旧确认不代表确认新版。撤回会留下明确状态与历史。教练不能代替其他账号确认，也不能修改别人的要求；回执只在当前授权范围内显示，管理员可审计。

“通知中心”显示官方安排的新增、移除、日期/时间、冰场、出场序号、明确热身组和个人时间的实质变化，包含修改前后、来源、文件哈希和检查时间。没有明确公布的个人时间或热身组保持空白。官网分组不作为热身组。

官方快照、变更日志和持久 outbox 使用同一个 D1 batch 事务；同一快照重跑不会创建新事件。站内通知以 outbox+账号作为唯一投递键。失败保留待发状态、重试时间和次数，过期处理租约可以恢复；同步任务及管理员“处理待发 / 重试队列”执行后续投递。每次读取、标记已读、回执和查看历史都会重新检查权限。
