# HSC Phase 2 管理员说明

## 登录与访问边界

原站点及原 D1 保持不变。首页为会员入口，`/workspace` 保留赛程、历史图表和筛选，`/coaches` 为管理员维护旧教练文本的页面。

支持两种身份入口：原 Sites/ChatGPT 登录，以及新增的自建用户名和密码。密码由 Better Auth 1.7.12 处理并保存加盐哈希，不存明文；用户名3–30位，注册密码12–128位，限速存于 D1。网页使用 HttpOnly cookie，手机使用库签名验证的 Bearer 会话并存于系统安全存储。角色选择、姓名、URL、邮箱字符串及客户端传入身份均不能授予权限。

自注册邮箱不视为已验证。即使管理员先批准了角色，自注册账号在接受通过已核实联系方式交付的邮箱绑定一次性邀请前，仍不能读取私人资料。现有 ChatGPT 会员若使用同邮箱创建密码账号，必须同时持有有效原 HSC/ChatGPT 会话和新密码会话，勾选明确关联；不会只凭邮箱相同合并身份。首次所有者管理员初始化只允许原 Sites 可信身份，密码自注册不能触发。

当前不发送邮箱验证或忘记密码邮件。请由本人保存好密码；不要让管理员收集明文密码。上线开放前应接入经批准的邮箱验证/找回服务并验收。原 ChatGPT 入口保留供所有者管理使用。生产签名密钥以 Sites Secret 保存，不进入 Git、手机包或前端。管理员“撤销会话”和本人“撤销全部 HSC 会话”同时撤销对应密码认证会话。

默认界面为英文，右上角可切换中文；语言选择保存在设备上。自填教练内容、姓名和官方原文不擅自翻译。

应用另有8小时服务端会员会话，cookie 为 `__Host-hsc_session`，设置 Secure、HttpOnly、SameSite=Lax。数据库仅存随机会话令牌的 SHA-256；每次请求重新检查账号状态、会话版本、会员准入和有效关系。退出、撤销会话、停用账号和解除关系分别立即生效。写操作必须来自同源 JSON 请求，并执行服务端限速。

首次设置必须在现有仅所有者可访问的边界内完成。已核实的站点所有者邮箱 `sherrylikeke@gmail.com` 首次进入会员入口时成为管理员，站点用户 ID 写入 `hsc-admin-bootstrap`，以后不会自动重新授予被撤销的管理员角色。其他账号先进入 pending 状态，不能读取私人赛程。最后一个管理员不能被停用、降级，或通过接受普通邀请意外降级。

## 会员准入和邀请

1. 用自己的账号打开首页，选 Admin，再点“进入会员入口”。
2. 在“会员管理”逐位核对候选选手。108位历史名单不是会员白名单，初始没有自动批准任何一位。确认训练关系、代表俱乐部与全名状态后勾选准入。
3. 核实家长、选手或教练本人的账号邮箱及身份。系统没有家长邮箱数据，不会从比赛名单推断监护人。未成年人的账号和家长关系必须由管理员明确确认。
4. 创建对应角色的邀请，明确选择允许绑定的选手。家长可多孩子，选手账号只能绑定一个本人资料，教练允许多人关联同一选手。教练文字候选名单不等于已验证账号。
5. 将一次性代码通过已确认的联系方式人工交给本人。代码只显示一次，数据库保存哈希，默认48小时到期。没有邮件自动发送；丢失时撤销旧邀请再生成。邀请只能由指定邮箱的已验证账号接受一次。
6. 受邀人在首页输入代码，接受后重新进入会员入口。没有邀请者可提交姓名匹配和身份核对申请；密码账号除会员审核外仍需邀请代码确认账号归属，不能仅批准其自填邮箱。同名选手用独立编号区分。
7. 名单外的人可以提交申请；管理员新增资料、确认准入，再邀请或明确绑定。家长可在账号已批准后逐个添加自己的孩子。

教练可通过工作区申请关联已有选手或提交新选手信息。所有新增/争议关联由管理员确认。批准后增加关系，不覆盖另一位教练。教练可主动解除自己的关系。账号换角色会撤销旧角色关系；停用、取消准入、解绑后每次 API 立即重新计算访问权。

保留 Breken 的 Hamilton 训练关系和比赛代表俱乐部差异。Nathaniel 全名未知时保持“全名 / 身份待确认”，不会按名字自动匹配官网记录。旧教练文本仍按用户保存的拼写显示；认证账号关系独立维护，不自动改写31条原始教练资料。

新增选手或由管理员确认全名后，下一次同步会重做官方名单和出场文件中的姓名匹配，即使文件内容哈希没有变化。未知身份继续排除，重复完整姓名不会自动合并。会员准入及账号关系仍需单独批准。

## 赛程与教练要求

管理员可查看所有候选、赛程与日志；Parent/Skater 仅获得已批准关系内的私人安排；Coach 获得自己关联选手的安排与汇总。赛事名称、官方文件、参赛公开名单、冰场、成绩来源属于公开赛事资料；会员身份、账号邮箱、私人备注、要求、回执和通知属于按关系隔离的资料。其他选手的历史档案 API 也会拒绝越权请求。

教练在“教练要求”选择一个或多个关联选手，填写准备、集合、装备或训练要求，可关联一场赛事及其官方分项、设置有时区的截止时间。发送者由服务端决定。家长/选手分别为每个孩子记录已读与确认；编辑产生新版本，旧确认不代表确认新版。撤回会留下明确状态与历史。教练不能代替其他账号确认，也不能修改别人的要求；回执只在当前授权范围内显示，管理员可审计。

“通知中心”显示官方安排的新增、移除、日期/时间、冰场、出场序号、明确热身组和个人时间的实质变化，包含修改前后、来源、文件哈希和检查时间。没有明确公布的个人时间或热身组保持空白。官网分组不作为热身组。

官方快照、变更日志和持久 outbox 使用同一个 D1 batch 事务；同一快照重跑不会创建新事件。站内通知以 outbox+账号作为唯一投递键。失败保留待发状态、重试时间和次数，过期处理租约可以恢复；同步任务及管理员“处理待发 / 重试队列”执行后续投递。每次读取、标记已读、回执和查看历史都会重新检查权限。

## 自动准备提醒与原生手机端

### 注册前名单校验与待定赛程

密码注册现在必须提交用户名、密码、申请身份（Skater / Parent / Coach）和 HSC 选手完整姓名，保留核验邮箱与密码确认。选手填写本人，家长填写孩子，教练填写拟关联的本俱乐部选手。服务端在创建认证账号之前检查管理员准入表：必须 admitted=1、在 HSC 训练、全名/身份已确认，且姓名唯一匹配；不根据108位历史候选或比赛代表俱乐部文字自动准入。名单尚未核实时请先在会员管理逐位确认，不要批量猜测。

通过名单检查只创建 pending 账号和带所选身份/选手的审核申请，不自动建立家长、教练关系或授予管理员角色。姓名同名不构成身份验证，仍需邀请归属核验及管理员批准。现有已验证管理员可在当前有效的 ChatGPT/HSC 会话下明确关联同邮箱密码凭据；这不是新增会员，也不能用前端勾选绕过服务端会话检查。

官方按出场序号范围拆开的时段，在未公布该选手对应分项的 Starting Order 时合并为一个待定分项。Carson 的短节目和自由滑各显示一项，共两项；主时间留空并显示“时间待确认”，候选范围和官方来源保留在展开详情中，不当成四项参赛安排。出场名单按字母排序的位置不作为出场序号。只有实际官方 Starting Order 才能确定对应时段；短节目序号不能决定自由滑时段。

网页版、个人赛程、教练总表与手机 API 共用这份聚合逻辑。待定分项不参加冲突判定或自动到场提醒，CSV不输出确定开始/结束时间。旧范围对应的人工备注不改写；不再对应当前分项的安排保留在待核对安排中。

“Reminders / 自动提醒”按账号和选手保存个人规则：携带清单、提前到场分钟数、提前提醒分钟数。默认提前90分钟到场、提前180分钟提醒；服务端拒绝到场不足60分钟或提醒比到场少提前60分钟的设置。只有准入选手及当前有效关系可设置和接收。后台在原有同步任务中处理持久提醒队列，重复运行不重复投递；官方时间调整、规则编辑/禁用或关系失效后会重新排期或取消。

采用比赛 IANA 时区处理夏令时。仅匹配确定的官方组别开始时间；不推算个人时间，不为未确认分组或夏令时歧义/不存在的当地钟点自动安排。站内投递仍受每小时任务延迟影响，不能称实时或保证准点。

`mobile/` 是同一私有仓库中的 Expo / React Native iOS、Android 共用源码，不是网页封装。已实现本机权限申请、安全存储、赛程/通知/回执/教练要求、双语和本机准备提醒。锁屏默认隐藏清单等私人详情；用户可单独开启。刷新或回到前台会重排本机提醒，登出会取消。本机离线时不能接收官网新修订，APNs/FCM 远程推送尚未接入。

手机端打包导出仅验证 JavaScript/Hermes 产物，不是签名 APK/IPA，更不是商店上架或真机验收。正式分发还需本人在官方页面完成开发者/签名账号登录、确认任何费用、隐私与账号删除流程和双平台真机测试。具体启动和发布边界见 `mobile/README.md`。不在聊天收集密码，不自动购买或提交商店。

用户已明确要求“内测接受后开放”。本次保持仅所有者私人访问，不改变站点外层访问策略，手机请求不会绕过该限制。验收通过并取得明确开放批准后才开放注册/登录入口；私人会员资料继续由应用认证、邀请归属确认和角色/选手关系保护。
